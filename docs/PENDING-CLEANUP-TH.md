# ล้างโพสต์ที่รออนุมัติ (Pending Cleanup)

หน้านี้ใช้ไล่เช็กทุกกลุ่มว่ามีโพสต์ของคุณค้างรอแอดมินอนุมัติอยู่กี่โพสต์ แล้วเลือกลบทีเดียว แทนที่จะต้องเข้าทีละกลุ่มแล้วกด Delete ทีละอัน

> ⚠️ **โพสต์ที่ลบแล้วกู้คืนไม่ได้** Facebook ไม่มีถังขยะสำหรับโพสต์ที่รออนุมัติ ระบบจะถ่ายภาพทุกโพสต์เก็บไว้ก่อนกดลบเสมอ แต่ตัวโพสต์เองหายถาวร

---

## ทำงานยังไง

ระบบเปิด URL `facebook.com/groups/<id>/my_pending_content` ของแต่ละกลุ่มโดยตรง — หน้าเดียวกับที่คุณกดปุ่ม **Manage posts** จากแถบ "Pending admin approval" ในหน้ากลุ่ม

การหาโพสต์ยึดจาก **ปุ่ม Delete** เป็นหลัก ไม่ได้ยึด class name ของ Facebook (ซึ่งเปลี่ยนตลอด)

จากการตรวจ DOM จริง Facebook **ไม่มีกล่องครอบต่อโพสต์** — เนื้อหาโพสต์กับแถวปุ่ม `Edit Delete` เป็น *พี่น้องกัน* และ ancestor ร่วมตัวแรกก็ครอบทุกโพสต์บนจอไปแล้ว ระบบจึงยึดปุ่ม Delete เป็นหลักหมุดของแต่ละโพสต์ แล้วถอยไปหา element ก่อนหน้าเพื่อเอาเนื้อหา

Facebook ยังเรนเดอร์ **ปุ่ม Delete ซ่อนซ้ำ** (`visibility: hidden` แต่มีขนาด 230×36 จริง) ระบบจึงเช็ค computed style ก่อนเสมอ ไม่ใช่แค่วัดขนาด

กดปุ่ม Delete บนการ์ดแล้ว Facebook จะเด้งกล่อง **Delete post?** ที่มีปุ่ม Cancel และ Delete ขึ้นมา ระบบรอให้กล่องปรากฏจริงก่อนแล้วจึงกด Delete ในกล่อง จากนั้นตรวจว่าการ์ดหายจากหน้าจริงจึงนับว่าสำเร็จ

---

## 3 ขั้นตอน

### 1 · เลือกขอบเขตแล้วตรวจ

เลือกว่าจะไล่เปิดกลุ่มไหนบ้าง ขั้นนี้ **ยังไม่ลบอะไรทั้งสิ้น** แค่เปิดนับ

| ขอบเขต | ใช้เมื่อไหร่ |
|---|---|
| **กลุ่มที่ระบบรู้ว่ามีของค้าง** | เร็วที่สุด ใช้ประวัติ `pending_review` ที่ระบบบันทึกไว้ตอนโพสต์เป็นตัวตั้ง |
| **กลุ่มที่เคยโพสต์** | ครอบคลุมกว่า รวมกลุ่มที่ระบบไม่ได้บันทึกสถานะไว้ |
| **ทุกกลุ่มในคลัง** | กวาดครบ ไม่มีตกหล่น แต่ช้าที่สุด |
| **เลือกเองจากคลังกลุ่ม** | ค้นหาและติ๊กเลือกเอง |

ระบบจะประมาณเวลาให้ก่อนเริ่ม (ราว 8 วินาทีต่อกลุ่ม)

> **หมายเหตุ:** ตัวเลข "กลุ่มที่ระบบรู้ว่ามีของค้าง" เป็นแค่เบาะแส ไม่ใช่ความจริง ณ ปัจจุบัน — แอดมินอาจอนุมัติหรือปฏิเสธไปแล้ว ระบบจึงยังต้องเปิดเช็กจริงทุกกลุ่มอยู่ดี ใช้เพื่อ**ตัดกลุ่มที่ไม่น่ามีของค้างออก**เท่านั้น

### 2 · เลือกกลุ่มที่จะลบ

ตารางจะโชว์เฉพาะกลุ่มที่มีของค้าง เรียงจากมากไปน้อย และติ๊กเลือกให้อัตโนมัติทุกกลุ่ม

- กดชื่อกลุ่มเพื่อกางดูรายละเอียดโพสต์ทีละอัน (ข้อความ วันที่ อายุ)
- กด **เปิดใน Facebook** เพื่อไปดูของจริงก่อนตัดสินใจ
- ติ๊กออกได้ตามต้องการ

### 3 · ยืนยันและลบ

ระบบจะลบโพสต์ค้าง **ทุกโพสต์** ในกลุ่มที่เลือกไว้

ติ๊กยืนยัน แล้วพิมพ์คำว่า **ลบ** ในกล่องที่เด้งขึ้นมาอีกชั้นก่อนระบบจะเริ่มทำงาน

> เดิมมีตัวเลือก "ลบเฉพาะที่เก่ากว่า N วัน" ด้วย แต่ถูกเอาออกเพราะอ่านวันที่จากหน้า Facebook ไม่ได้ (ดูหัวข้อถัดไป)

## กลไกความปลอดภัย

| กลไก | รายละเอียด |
|---|---|
| **ถ่ายภาพก่อนลบ** | ทุกโพสต์ถูก screenshot เก็บไว้ที่ `data/pending-cleanup/<รหัสงาน>/<ชื่อกลุ่ม>/` ก่อนกด Delete กดดูย้อนหลังได้จากปุ่ม "ดูหลักฐาน" |
| **นับไม่ตรง = แจ้งเตือน** | ถ้าหน้าเว็บบอกว่ามีของค้างแต่ระบบอ่านการ์ดไม่เจอ จะรายงานว่ากลุ่มนั้น "ไม่สำเร็จ" แทนที่จะบอกว่าไม่มีของค้าง |
| **ยืนยัน 2 ชั้น** | ติ๊ก checkbox + พิมพ์คำว่า "ลบ" |
| **หยุดกลางคันได้** | กด "หยุดหลังจบรายการปัจจุบัน" ได้ตลอดทั้งตอนตรวจและตอนลบ |
| **กันชนกับงานอื่น** | ล้าง Pending, สแกนคลังกลุ่ม และคิวโพสต์ ใช้ Browser ตัวเดียวกัน จึงทำพร้อมกันไม่ได้ ระบบบล็อกให้เอง |
| **ตรวจ Checkpoint** | เจอหน้า CAPTCHA/ยืนยันตัวตน จะหยุดทันที ไม่กดต่อ ถ้าเปิดหลายแท็บ ทุกแท็บจะหยุดพร้อมกัน |
| **JSON snapshot** | ผลทั้งหมดถูกเขียนเป็นไฟล์ JSON ดาวน์โหลดได้ |

## ทำหลายแท็บพร้อมกัน

ตัวเลือก **"พร้อมกัน N แท็บ"** อยู่ข้างปุ่มเริ่มตรวจและปุ่มเริ่มลบ เลือกได้ 1, 2, 3, 5, 8 หรือ 10 แท็บ (ค่าเริ่มต้น 3) ระบบจำค่าที่เลือกล่าสุดไว้ในเบราว์เซอร์

- แต่ละแท็บเปิดเป็น **หน้าต่าง Chromium แยก** แล้วหยิบกลุ่มถัดไปจากคิวเดียวกัน กลุ่มหนึ่งจึงถูกทำโดยแท็บเดียวเสมอ ไม่ลบซ้ำกัน
- ใช้หน้าต่างแยกเพราะ Facebook โหลดรายการโพสต์ค้างแบบ lazy-load ถ้าซ่อนเป็นแท็บพื้นหลัง รายการอาจโหลดไม่ขึ้น
- แท็บจะเปิดห่างกันทีละ 2 วินาที (`HR_AUTO_PENDING_TAB_STAGGER_MS`) เพื่อไม่ให้ยิงเข้า Facebook พร้อมกันทีเดียว
- ข้อความสถานะของแต่ละกลุ่มจะบอกว่าอยู่ใน "แท็บ 1", "แท็บ 2" …
- ถ้าแท็บไหนเจอหน้าตรวจความปลอดภัย **ทุกแท็บหยุดทันที** แม้จะอยู่กลางกลุ่ม

> ⚠️ **ทุกแท็บคือบัญชี Facebook เดียวกัน** ยิ่งเปิดหลายแท็บ บัญชีก็ยิ่งลบเร็วขึ้นเป็นเท่าตัว ตัวเลขที่ปลอดภัยคือ 2–3 แท็บ ถ้าเกิน 5 แท็บ Facebook มีโอกาสมองว่าเป็นพฤติกรรมอัตโนมัติและขึ้น checkpoint หน้าเว็บจะขึ้นคำเตือนเมื่อเลือกเกิน 5

**เวลาโดยประมาณ:** ระบบหารเวลาตรวจด้วยจำนวนแท็บ แต่ของจริงจะไม่เร็วขึ้นตรงตัว เพราะทุกแท็บใช้เน็ตและเครื่องเดียวกัน

## รูปแบบวันที่ที่ระบบอ่านได้

| รูปแบบ | ตัวอย่าง |
|---|---|
| แบบสัมพัทธ์ | `3d` · `14 days` · `6h` · `2w` · `5 วัน` · `3 ชม.` |
| เมื่อวาน | `Yesterday` · `เมื่อวาน` |
| อังกฤษเต็ม | `25 August at 08:33` · `25 Aug at 08:33` · `August 25 at 08:33` |
| ไทย | `25 สิงหาคม` · `25 ส.ค.` · `25 สิงหาคม 2568` (แปลง พ.ศ. → ค.ศ. ให้) |

**ถ้าไม่มีปีระบุ** ระบบจะถือว่าเป็นปีปัจจุบัน แต่ถ้าคำนวณแล้วตกในอนาคต จะถอยไปปีก่อนหน้าให้อัตโนมัติ (เช่นเห็น `25 August` ตอนวันที่ 11 สิงหาคม แปลว่าโพสต์นั้นคือปีที่แล้ว)

**อ่านไม่ออก** → แสดงเป็น "อ่านวันที่ไม่ได้" และถูกข้ามในโหมดกรองอายุ

> ⚠️ **ข้อจำกัดที่ทดสอบกับหน้าจริงแล้ว:** Facebook **สแครมเบิลข้อความวันที่โดยเจตนา** เพื่อกัน scraping — ตัวอักษรถูกสลับลำดับใน DOM แล้วจัดเรียงกลับด้วย CSS ค่าที่ดึงได้จึงเป็นขยะ เช่น `drtneoospSfut3g L0cM84ua...`
>
> ผลคือ **ตัวเลือก "ลบเฉพาะที่เก่ากว่า N วัน" ถูกเอาออกจากหน้าเว็บแล้ว** เพราะมันจะข้ามทุกโพสต์จนไม่ได้ลบอะไรเลย ตัวรองรับยังอยู่ในฝั่งเซิร์ฟเวอร์เผื่อ Facebook เลิกซ่อนวันที่ในอนาคต

## ตั้งค่าเพิ่มเติม

| ตัวแปร | ค่าเริ่มต้น | หน้าที่ |
|---|---|---|
| `HR_AUTO_PENDING_SCAN_DELAY_MS` | `1500` | เว้นระยะระหว่างเปิดแต่ละกลุ่มตอนตรวจ |
| `HR_AUTO_PENDING_DELETE_DELAY_MS` | `2500` | เว้นระยะระหว่างลบแต่ละโพสต์ |
| `HR_AUTO_PENDING_CONFIRM_TIMEOUT_MS` | `10000` | เวลารอกล่องยืนยัน **Delete post?** ปรากฏหลังกด Delete บนการ์ด |
| `HR_AUTO_PENDING_TABS` | `3` | จำนวนแท็บเริ่มต้น เมื่อคำขอไม่ได้ระบุมา (1–10) หน้าเว็บส่งค่าที่เลือกไว้มาเองทุกครั้ง |
| `HR_AUTO_PENDING_TAB_STAGGER_MS` | `2000` | เว้นระยะระหว่างเปิดแต่ละแท็บ |
| `HR_AUTO_FACEBOOK_LOAD_TIMEOUT_MS` | `45000` | เวลารอ Facebook โหลดหน้า (ใช้ร่วมกับการโพสต์) |

เพิ่มค่าหน่วงถ้าเน็ตช้าหรือกังวลเรื่องอัตราการยิงคำสั่ง

## ปัญหาที่พบบ่อย

**กลุ่มขึ้นว่า "เปิดไม่สำเร็จ"**
เข้ากลุ่มไม่ได้ ถูกเตะออกจากกลุ่ม หรือ Facebook โหลดไม่ทัน — เปิดดูใน Facebook เองแล้วลองตรวจใหม่

**ขึ้นว่า "แอดมินยังไม่อนุมัติการเป็นสมาชิก"**
Facebook ขึ้น "Your review is still pending" — เรายังเป็นสมาชิกรออนุมัติ หน้านี้ **ไม่มีปุ่ม Delete** มีแค่ Cancel Request ซึ่งจะยกเลิกคำขอเข้ากลุ่มไปด้วย ระบบจึงไม่กดให้ ถ้าต้องการล้างจริงให้กด Cancel Request เองใน Facebook

**ขึ้นว่า "เปิดกลุ่มไม่ได้ (This content isn't available)"**
ออกจากกลุ่มแล้ว ถูกนำออก หรือกลุ่มถูกลบ — ไม่มีอะไรให้ลบจากฝั่งเรา

**ขึ้นว่า "หน้าบอกว่ามี N โพสต์ค้าง แต่ระบบอ่านการ์ดไม่ได้" หรือ "รอโพสต์ค้างโหลดจนหมดเวลา"**
Facebook โหลดรายการไม่ทันภายในเวลาที่กำหนด ระบบเก็บ **ภาพหน้าจอ + ข้อความบนหน้า** ไว้ให้แล้วที่ `data/pending-cleanup/<รหัสงาน>/diagnostics/` เปิดดูได้ว่าตอนนั้นหน้าจอเป็นอย่างไร ถ้าเน็ตช้าให้เพิ่ม `HR_AUTO_FACEBOOK_LOAD_TIMEOUT_MS`

**ขึ้นว่า "เปิดหน้าแล้วแต่ไม่พบโพสต์ค้างให้ลบ"**
ตอนตรวจเจอโพสต์ แต่ตอนกลับมาลบหน้ากลับว่าง — แปลว่ารายการโหลดไม่ทัน ระบบจะรายงานเป็น **ไม่สำเร็จ** ไม่ใช่ "ลบเสร็จ 0" และเก็บภาพหน้าจอไว้ให้ ลองสั่งลบใหม่อีกครั้ง

**ขึ้นว่า "กดลบแล้วแต่ไม่พบปุ่มยืนยันในกล่อง Delete post?"**
ระบบกด Delete บนการ์ดแล้ว แต่รอกล่องยืนยันจนหมดเวลา — เน็ตช้าหรือ Facebook เปลี่ยนหน้าตากล่อง ลองเพิ่ม `HR_AUTO_PENDING_CONFIRM_TIMEOUT_MS` (ค่าเริ่มต้น 10000)

**ขึ้นว่า "กดยืนยันในกล่อง Delete post? แล้วแต่โพสต์ยังอยู่"**
กดยืนยันไปแล้วแต่การ์ดไม่หายจากหน้า ลองตรวจกลุ่มนั้นด้วยตนเอง ภาพหลักฐานยังถูกเก็บไว้ให้แล้ว

**ไม่มีกลุ่มให้เลือกเลย**
กลุ่มต้องมี `external_id` ซึ่งได้จากการสแกนจาก Facebook หรือ import — กลุ่มที่กรอก URL เองแบบผิดรูปแบบจะไม่มี
