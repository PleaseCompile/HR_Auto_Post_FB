# คู่มือ HR Auto

[ศูนย์รวมเอกสาร](README.md) · [ติดตั้ง Windows](INSTALL-WINDOWS-TH.md) · [ติดตั้ง Linux](INSTALL-LINUX-TH.md) · [แก้ปัญหา](TROUBLESHOOTING-TH.md)

> ระบบปัจจุบันเป็นเครื่องมือ Assisted/Hybrid ผู้ใช้ต้องตรวจและยืนยันก่อนโพสต์จริง ใช้เฉพาะบัญชีและกลุ่มที่มีสิทธิ์ และหยุดทันทีเมื่อพบ CAPTCHA, Checkpoint หรือข้อจำกัดบัญชี

## รูปแบบการทำงาน

| รูปแบบ | พฤติกรรม | เหมาะกับ |
|---|---|---|
| Dry run | เปิดกลุ่ม ตรวจว่ามีพื้นที่โพสต์ และเก็บหลักฐาน แต่ไม่กรอกหรือส่งโพสต์ | ตรวจกลุ่มใหม่ |
| Assisted · ทีละกลุ่ม | เปิดแท็บใหม่หนึ่งกลุ่ม เตรียมข้อความ/รูป และรอคำสั่งก่อนทำกลุ่มถัดไป | งานที่ต้องตรวจละเอียด |
| Assisted · Hybrid | เลือกเปิดทุกกลุ่มพร้อมกัน หรือกำหนดเพดานแท็บเอง | คิวหลายกลุ่มที่ไม่ต้องการให้กลุ่มเดียวบล็อกทั้งหมด |

ค่าเริ่มต้นของคิวโพสต์จริงคือ Hybrid แบบ `ทั้งหมด` ระบบจะทยอยเตรียมแท็บของทุกกลุ่มที่เลือกโดยไม่มีเพดาน เหมาะกับเครื่องสเปกสูง เช่น RAM 32 GB หากต้องใช้เครื่องสเปกต่ำสามารถเลือกเพดาน 2, 3, 4, 5, 10 หรือ 20 แท็บได้

## ความหมายของสถานะ

- `รอเริ่ม`: ยังไม่ได้เปิดกลุ่ม
- `กำลังเปิดกลุ่ม`: กำลังสร้างแท็บ Facebook ใหม่
- `กำลังเตรียมโพสต์`: กำลังกรอกข้อความและอัปโหลดรูป
- `รอยืนยัน`: โพสต์ถูกเตรียมไว้แล้ว แต่ยังไม่ได้ส่ง
- `กำลังส่ง`: ระบบได้รับคำยืนยันและกำลังกด Post
- `เผยแพร่แล้ว`: ส่งสำเร็จหรือผู้ใช้ยืนยันว่าโพสต์เองแล้ว
- `รอแอดมินอนุมัติ`: Facebook รับโพสต์แล้วแต่กลุ่มต้องอนุมัติ
- `ข้ามแล้ว`: ไม่ได้ส่งโพสต์และมีภาพหลักฐานก่อนปิดแท็บ
- `ต้องตรวจด้วยตนเอง`: แอปถูกปิดหรือหยุดในช่วงที่ผลการส่งยังไม่แน่นอน
- `ไม่สำเร็จ`: เปิดกลุ่ม เตรียมโพสต์ หรือส่งโพสต์ไม่สำเร็จ

สถานะ `รอยืนยัน` ไม่ใช่ข้อผิดพลาดและไม่มี timeout ระบบจะรอผู้ใช้ โดย Hybrid จะทำกลุ่มอื่นต่อจนเปิดครบทุกกลุ่ม หรือครบเพดานที่ผู้ใช้กำหนด

### สีของกรอบสถานะ

- เขียว: งานเสร็จแล้วหรือเผยแพร่แล้ว
- น้ำเงิน: ระบบกำลังเปิด เตรียม หรือส่งโพสต์
- ส้ม: รอผู้ใช้ยืนยัน รอแอดมิน หรือจำเป็นต้องตรวจด้วยตนเอง
- แดง: รายการไม่สำเร็จ
- เทา: รอเริ่ม ข้าม หรือหยุดแล้ว

กรอบใหญ่ของคิวแสดงสถานะรวม ส่วนแถบสีด้านซ้ายของแต่ละกลุ่มแสดงผลเฉพาะกลุ่มนั้น จึงอาจมีหลายสีอยู่ภายในคิวเดียวกันได้

## ปุ่มระหว่างรอยืนยัน

### เปิดแท็บ

นำแท็บ Facebook ของกลุ่มนั้นขึ้นมาด้านหน้า โดยไม่เปลี่ยนสถานะ

### ยืนยันและโพสต์

ใช้เมื่อข้อความ รูป และชื่อกลุ่มถูกต้อง ระบบจะคลิก Post จริง เก็บภาพหลักฐาน และปิดแท็บเมื่อจบ

### ฉันโพสต์เองแล้ว

ใช้เมื่อผู้ใช้กด Post ใน Facebook ด้วยตนเอง ระบบจะไม่กดซ้ำ แต่จะเก็บหลักฐาน บันทึกว่าเผยแพร่แล้ว และปิดแท็บ

### ข้าม + หลักฐาน

ระบบจะถามเหตุผลแบบไม่บังคับ แคปหน้าต่างโพสต์ก่อนปิด บันทึกสถานะข้าม แล้วเปิดพื้นที่ให้กลุ่มถัดไปใน Hybrid

## ขั้นตอน Hybrid ที่แนะนำ

1. เลือก Draft และกลุ่ม
2. เลือก `โพสต์จริงแบบ Assisted`
3. เลือก `Hybrid` และ `ทั้งหมด` สำหรับเครื่อง RAM 32 GB หรือเลือกเพดานเองเมื่อต้องการ
4. สร้างคิวและกด `เริ่มคิว`
5. ระบบทยอยเตรียมแท็บ Facebook จนครบทุกกลุ่มที่เลือก
6. ตรวจทีละแท็บ แล้วเลือก `ยืนยันและโพสต์`, `ฉันโพสต์เองแล้ว` หรือ `ข้าม + หลักฐาน`
7. เมื่อแท็บหนึ่งจบ ระบบปิดแท็บและเตรียมกลุ่มถัดไป
8. ตรวจหน้าหลักฐานเมื่อคิวเสร็จ

## การหยุดและกู้คืน

- `พัก`: หยุดการเตรียมแท็บใหม่ แท็บที่รอยืนยันยังอยู่และยังตัดสินใจได้
- `หยุด`: เก็บหลักฐานของแท็บที่ยังรอ เปลี่ยนเป็น `ต้องตรวจด้วยตนเอง` และไม่ส่งโพสต์
- หากแอปถูกปิดระหว่างรอยืนยัน รายการนั้นจะเป็น `ต้องตรวจด้วยตนเอง` เพื่อป้องกันการโพสต์ซ้ำ
- หากตรวจพบว่าโพสต์ไปแล้ว ให้กด `ยืนยันว่าโพสต์เองแล้ว` ระบบจะเปิดกลุ่ม เก็บหลักฐานย้อนหลัง และไม่กด Post
- คิวที่ `รอเริ่ม`, `ถูกขัดจังหวะ` หรือ `หยุดแล้ว` สามารถเปลี่ยนระหว่างทีละกลุ่มกับ Hybrid ก่อนเริ่มต่อ

## ลบทั้งคิวและโพสต์ใหม่ทั้งหมด

ระบบมี 2 วิธี:

- `ลบทั้งคิว` ลบเฉพาะคิวใบนั้น เหมาะเมื่อ Draft เดียวกันไม่มีคิวเก่าใบอื่น
- `ล้างคิวเดิมทั้งหมดและสร้างใหม่` ลบทุกคิวที่อ้าง Draft ที่เลือก แล้วสร้างคิวใหม่จากกลุ่มที่กำลังเลือกในคำสั่งเดียว เหมาะเมื่อข้อความแจ้งว่ามีกลุ่มเคยถูกส่ง หรือไม่ทราบว่าคิวเก่าใบใดกำลังขวาง

วิธีเริ่มใหม่ทั้งหมดที่แนะนำ:

1. ถ้ามีคิวกำลังทำงาน ให้กด `หยุด` และรอให้แท็บของคิวปิดครบ
2. ตรวจ Facebook โดยเฉพาะรายการ `ต้องตรวจด้วยตนเอง`, `เผยแพร่แล้ว` และ `รอแอดมินอนุมัติ`
3. ไปหน้า `คลังกลุ่ม` เลือกกลุ่มทั้งหมดที่จะนำเข้าคิวใหม่
4. เลือก Draft, โหมด, รูปแบบ Hybrid/ทีละกลุ่ม และจำนวนแท็บ
5. กด `ล้างคิวเดิมทั้งหมดและสร้างใหม่`
6. อ่านคำเตือน แล้วพิมพ์ `เริ่มใหม่ทั้งหมด`
7. ระบบจะลบทุก Run, เป้าหมาย และหลักฐานที่อ้าง Draft นั้น ก่อนสร้างคิวใหม่จากกลุ่มที่เลือก
8. Draft ข้อความ รูปต้นฉบับ และคลังกลุ่มจะยังอยู่

การลบและสร้างใหม่ทำในธุรกรรมฐานข้อมูลเดียวกัน หากสร้างคิวใหม่ไม่สำเร็จ ระบบจะย้อนการลบฐานข้อมูลกลับ ไม่ทิ้งสถานะครึ่งทาง

ระบบไม่อนุญาตให้ลบคิวที่ยัง `กำลังทำงาน`, `รอยืนยัน`, `พักชั่วคราว` หรือมีรายการ `กำลังส่ง` ต้องหยุดและตรวจ Facebook ก่อน ส่วนคิวที่มีผลสำเร็จสามารถลบได้หลังพิมพ์คำยืนยัน

> การลบคิวจะลบหลักฐานของคิวนั้นด้วย หากต้องเก็บภาพไว้ ให้อัปโหลดหรือสำรองออกจากระบบก่อนลบ

## การอัปโหลดและจัดการหลักฐานเอง

ทุกแถวของกลุ่มในหน้าคิวมีปุ่ม `จัดการหลักฐาน` ใช้เพิ่มภาพที่แคปจากโทรศัพท์หรือเบราว์เซอร์อื่นได้ แม้รายการนั้นจะไม่สำเร็จ ถูกข้าม หรือกำลังรอตรวจสอบ

1. กด `จัดการหลักฐาน` ที่กลุ่มที่ต้องการ
2. เลือกรูปได้พร้อมกันสูงสุด 5 รูปต่อครั้ง รองรับ JPG, PNG, WebP และ GIF รูปละไม่เกิน 20 MB
3. ใส่หมายเหตุ เช่น ช่องทางที่แคปหรือผลการตรวจ แล้วกด `อัปโหลดหลักฐาน`
4. แก้ข้อความในช่องหมายเหตุแล้วกด `บันทึกหมายเหตุ`
5. กด `เปลี่ยนรูป` เมื่อต้องการแทนที่ไฟล์เดิม โดยหมายเหตุเดิมจะยังอยู่
6. กด `ลบ` และยืนยันเมื่อต้องการลบไฟล์ออกจากเครื่อง

หลักฐานที่ระบบแคปอัตโนมัติจะแสดงว่า `ระบบสร้าง` และเปิดดูได้อย่างเดียว เพื่อรักษาประวัติการทำงาน ส่วนหลักฐานที่เพิ่มเองจะแสดงว่า `อัปโหลดเอง` และแก้ไขหรือลบได้ ทั้งสองแบบรวมอยู่ในหน้า `หลักฐาน`

## ตัวกรองคลังหลักฐาน

ค่าเริ่มต้นที่แนะนำคือ `จัดกลุ่มตามรอบคิว` + `ยึดวันที่งานของรอบ` + `ล่าสุดก่อน` เพราะทำให้เห็นผลรวมของแต่ละรอบและรายการผิดพลาดภายในรอบเดียวกันได้ทันที

| ตัวกรอง | ใช้ตอบคำถาม | เหตุผลที่มีประโยชน์ |
|---|---|---|
| ช่วงด่วน | วันนี้, 7 วันล่าสุด, เดือนนี้ หรือทั้งหมด | เปิดรายงานประจำวัน/สัปดาห์ได้ในคลิกเดียว |
| ค้นหาหลายคำ | ชื่อกลุ่ม หมายเหตุ สถานะ เลขคิว | ใช้ค้นหาข้ามหลายช่องโดยไม่ต้องจำว่าข้อมูลอยู่คอลัมน์ใด |
| ยึดวันที่จาก | วันที่งานของรอบ หรือวันที่เก็บหลักฐานจริง | แยกวันที่หัวหน้ามอบหมายงานออกจากวันที่ทำงานจริง |
| ตั้งแต่วันที่–ถึงวันที่ | งานในช่วงวันที่ใด | เหมาะกับสรุปรายสัปดาห์ รายเดือน และตรวจย้อนหลัง |
| ช่วงโพสต์ | เช้า กลางวัน หรือเย็น | แยกรอบงานประจำวันตามช่วงที่ได้รับมอบหมาย |
| รอบคิว | คิว/Run ใดโดยเฉพาะ | ใช้ตรวจผลลัพธ์ของการกดสร้างคิวแต่ละครั้ง แม้วันและช่วงเวลาจะซ้ำกัน |
| กลุ่ม | หลักฐานของกลุ่มใด | ใช้ดูประวัติของกลุ่มเดียวหรือหาปัญหาซ้ำ |
| สถานะโพสต์ | เผยแพร่ ไม่สำเร็จ รอตรวจ ฯลฯ | ใช้แยกงานที่ต้องแก้หรือทบทวนออกจากงานที่สำเร็จ |
| ที่มาหลักฐาน | ระบบสร้างหรืออัปโหลดเอง | ตรวจว่าหลักฐานมาจากระบบอัตโนมัติหรือผู้ใช้เพิ่มภายหลัง |
| เก็บหลังเวลา–ก่อนเวลา | หลักฐานถูกเก็บจริงช่วงกี่โมง | ใช้ตรวจรอบเวลาทำงานหรือค้นหาเหตุการณ์ในช่วงเวลาหนึ่ง รองรับช่วงข้ามเที่ยงคืน |
| มุมมอง | จัดกลุ่มตามรอบคิวหรือรายการรวม | แบบรอบเหมาะกับตรวจงาน; แบบรวมเหมาะกับค้นหาและเรียงข้ามรอบ |
| เรียงลำดับ | ล่าสุดก่อน เก่าสุดก่อน หรือชื่อกลุ่ม ก–ฮ | เลือกตามงานตรวจล่าสุด งานย้อนหลัง หรือเช็กรายชื่อกลุ่ม |

ช่องค้นหาใช้เทคนิคเดียวกับคลังกลุ่ม:

- เว้นวรรค หมายถึงต้องมีครบทุกคำ เช่น `หางาน อยุธยา`
- `|` หมายถึง “หรือ” เช่น `อยุธยา | สระบุรี`
- ใส่เครื่องหมายคำพูดเพื่อค้นหาวลี เช่น `"รอแอดมิน"`
- ใส่ `-` หน้าคำเพื่อไม่เอาคำนั้น เช่น `อยุธยา -ร้านอาหาร`

ชุดตัวกรองที่แนะนำ:

- ตรวจงานรอบเดียว: เลือก `รอบคิว` และใช้มุมมอง `จัดกลุ่มตามรอบคิว`
- หางานที่ต้องแก้: เลือกวันที่/ช่วงโพสต์ แล้วตั้งสถานะเป็น `ไม่สำเร็จ` หรือ `ต้องตรวจด้วยตนเอง`
- สรุปผลงานประจำวัน: กด `วันนี้` เลือก `วันที่งานของรอบ` และเรียง `ล่าสุดก่อน`
- ตรวจสิ่งที่ทำจริงนอกเวลางาน: เลือก `วันที่เก็บหลักฐานจริง` และกำหนดเวลาเริ่ม–สิ้นสุด
- ตรวจหลักฐานที่เพิ่มภายหลัง: เลือกที่มา `อัปโหลดเอง`
- ตรวจกลุ่มซ้ำหลายรอบ: เลือกกลุ่มเดียว เปลี่ยนมุมมองเป็น `รายการรวมทั้งหมด` และเรียง `เก่าสุดก่อน`

## ข้อควรระวัง

- หากพบ CAPTCHA, checkpoint, แบบสอบถาม หรือข้อจำกัดบัญชี ให้หยุดคิวและจัดการด้วยตนเอง
- อย่าเริ่มคิวซ้ำสองคิวด้วย Draft และกลุ่มเดียวกัน
- เครื่องที่มีหน่วยความจำน้อยควรกำหนดเพดานแท็บเอง ส่วนเครื่อง RAM 32 GB สามารถใช้ `ทั้งหมด` ได้
- ตรวจข้อความ รูป และชื่อกลุ่มทุกครั้งก่อนยืนยันโพสต์จริง
- การลบหลักฐานที่อัปโหลดเองจะลบไฟล์ออกจากเครื่องและกู้คืนจากแอปไม่ได้

## ล้างข้อมูลคิวและหลักฐานสำหรับเริ่มงานจริง

ปิดคิวและ Browser Session ก่อน แล้วรันคำสั่งต่อไปนี้จากโฟลเดอร์โปรเจกต์:

```bash
npm run reset:queue-evidence
```

คำสั่งนี้ลบเฉพาะคิว รายการเป้าหมาย และไฟล์หลักฐานทั้งหมด โดยไม่ลบ Draft รูปต้นฉบับ รายชื่อกลุ่ม ข้อมูลสแกนกลุ่ม หรือ Browser Profile
